Now that target-http is implemented and working nicely we can implement a grpc target.

service is started from cmd/target-grpc

the internals must be created in internal/target-grpc

create a contract in internal/contracts called target.proto. In must implement the use cases documented in instructions-use-cases.txt.

The target service must implement prometheus metrics for every use case. This is so that we can display the test run on a grafana dashboard. Each use case must be mapped to a path and the path can be the name of the use case. no need to stick to restull semantics. Use case name with dashes for example use-case-name. 

the target service must read environment variables for the port to listen on and the metrics port to listen on.

manifest/target-grpc should be created for the eventual deployment into a k8s cluster.

The master server must contain configuration for all the use-cases. we must be able to select a use-case to test and then trigger the agents that are connected to run the use-case.

from a chaos master perspective it is still using the same use cases and the target already has support for grpc. 

The agent will use the grpc client instead of an http client to run use cases when the target type is grpc.
